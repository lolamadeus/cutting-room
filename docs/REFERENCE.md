# Cutting Room: reference

Commands, project layout and file formats. All commands run from the repo root; they need Python 3.10+ and ffmpeg.
No pip packages are needed for the core tools.

## Commands

| Command | What it does |
| --- | --- |
| `python engine/doctor.py` | Check Python / ffmpeg / optional extras and list projects with their state |
| `python engine/demo.py` | Make `projects/demo` from generated test footage |
| `python engine/new_project.py "Title" <folder>... [--id x] [--kind ...] [--brief ...] [--target 120 180] [--recursive]` | Scaffold a project |
| `python engine/prepare.py <id> [--jobs 3] [--force]` | Build proxies, thumbs, filmstrips, waveforms and `clips.json`. Re-run when clips are added; only new or changed files are processed |
| `python engine/serve.py [--open [<id>]]` | Run the local server on <http://localhost:8770/> (the launchers call this) |
| `python engine/export_brief.py <id>` | Review → `edit/selects.json` + `edit/brief.md` |
| `python engine/inspect_regions.py <id>` | Contact sheets (`edit/sheets/`) + loudness per second and onsets for every highlight |
| `python engine/inspect_regions.py <id> <clip> <start> <end>` | The same for one region (use `0 <dur>` for a whole clip) |
| `python engine/render.py <id> <edl.json> [--jobs 4]` | Render an edit decision list to `edit/renders/<name>.mp4` |

Downloading footage (needs `pip install yt-dlp`):

```bash
python -m yt_dlp -f "bv*+ba/b" --merge-output-format mp4 -o "<source folder>/<name>.%(ext)s" <url>
```

## Project layout

```
projects/<id>/
  project.json          settings (you or Claude edit this)
  review.json           your marks, written by the editor
  backups/              snapshots of review.json and render-notes.json (every 10 min while editing, last 40 kept)
  _cache/               generated by prepare.py: proxy/ thumbs/ strips/ waves/ clips.json  (safe to delete)
  edit/
    brief.md, selects.json         from export_brief.py
    make_edl_vN.py                 Claude's script that writes each version's EDL
    edl_<name>.json                edit decision lists
    CUT_vN.md                      Claude's summary of each version
    sheets/                        contact sheets from inspect_regions.py
    renders/<name>.mp4             renders, plus <name>.txt (report) and <name>.plan.json (segment timeline)
    render-notes.json              your notes on renders, written by the notes page
    cache/                         render cache (segments, loudness); safe to delete
  Open editor.bat / open-editor.sh
```

## project.json

| key | what it does |
| --- | --- |
| `title`, `kind`, `brief`, `accent` | shown in the hub and editor. `accent` is a CSS colour |
| `source` | folder, or list of folders, holding the clips. Can be `[]` when `files` is used |
| `recursive` | `true` to include subfolders |
| `exclude` | list of regexes; matching file names are skipped |
| `files` | explicit clips from anywhere: paths, or `{ "path", "group" }` objects |
| `target` | `{ "min": 120, "max": 180 }` seconds: drives the Board's length meter |
| `groups` | ordered list of clip-list sections |
| `groupRules` | `[{ "match": "<regex on filename>", "group": "<name>" }]`, first match wins (clips can also be regrouped in the editor) |
| `highlightTags` | tag sets: `{ "id", "label", "mode": "single" \| "multi", "board": true, "options": [{ "id", "label", "color" }] }`. The set with `board: true` defines the Board's sections (and `Shift`+number shortcuts) |
| `priorities` | optional; defaults to Must / Try / If there's space / Don't use (`must`, `try`, `space`, `dont`) |

## review.json (written by the editor)

```jsonc
{
  "v": 1,
  "savedAt": 1763380000000,            // ms since epoch; on load the newer of this file and the browser's copy wins
  "clips": {
    "<clip id>": {
      "prio": "must",                   // must | try | space | dont, or absent
      "group": "...",                   // optional: moved to another group in the editor
      "notes": "clip-level notes",
      "hl": [
        { "id": "a1b2c3d4", "s": 12.3, "e": 18.0, "note": "", "key": false,
          "tags": { "cat": "combat", "focus": ["sfx", "mix"] } }   // single sets: an id; multi sets: a list
      ]
    }
  },
  "order": ["<highlight id>", ...],     // Board running order
  "boardGroups": ["<category id>", ...],// Board section order
  "boardPrios": ["must", "try", ...],   // which priorities count on the Board
  "notes": "edit direction (Board notes box)"
}
```

Clip ids are file names without the extension (with the extension or a short hash added if two files clash).

## Edit decision list (EDL)

```jsonc
{
  "name": "reel_v1",                   // output: edit/renders/reel_v1.mp4
  "width": 1920, "height": 1080, "fps": 60,
  "loudness": { "target": -13, "peakAllowance": 1.5, "ceiling": -1.0, "maxBoost": 12 },
  "defaults": { "fadeIn": 0.012, "fadeOut": 0.012, "tail": 0 },
  "segments": [
    { "clip": "<clip id>", "in": 12.3, "out": 15.8, "section": "Combat", "label": "what this is",
      "fadeIn": 0.05, "fadeOut": 0.3,  // audio fades, seconds
      "tail": 0.35,                    // L-cut: audio carries on past the cut, fading under the next segment
      "vFadeIn": 0.3, "vFadeOut": 0.3, // picture fades from / to black
      "blackFrom": 51.95,              // picture goes black from this source time; audio continues
      "crop": [x, y, w, h],            // use only this rectangle of the source (source pixels)
      "gain": -2 }                     // manual trim in dB on top of the normalisation
  ]
}
```

**Loudness:** each segment is measured (integrated LUFS, true peak) and gain-matched to `target`. It's plain gain, no
compression, so dynamics are kept. Gain is capped so a segment's peaks only push `peakAllowance` dB into a
4×-oversampled master limiter at `ceiling` dBTP, and never boosted by more than `maxBoost`.

**Caching:** segment loudness and rendered segments are cached in `edit/cache/`, keyed by their settings, so changing
one cut only re-renders that segment.

Outputs next to the video: `<name>.txt` (timeline with each segment's measured level and applied gain, plus master
loudness) and `<name>.plan.json` (the segment timeline the notes page uses).

## render-notes.json (written by the notes page)

```jsonc
{
  "renders": {
    "<file>.mp4": {
      "overall": "notes on the whole render",
      "notes": [
        { "id": "oyy1ltk", "s": 10.35, "e": 14.07,     // time in the render; e is null for a point note
          "kind": "change",                           // change | cut | mix | love
          "text": "cut this, it duplicates earlier sounds",
          "seg": 2, "clip": "<clip id>", "src": 76.95, // segment number, source clip, time in the source clip
          "label": "segment label from the EDL",
          "status": "open",                            // open | done
          "reply": "Done in v2: ...",                  // shown under the note
          "created": "2026-11-17T10:55:32.158Z" }
      ]
    }
  },
  "savedAt": "..."
}
```

When acting on notes, only `status` and `reply` should be changed; everything else is the user's.

Renders named `<base>_final.mp4`, `<base>_share.mp4` or `<base>_captioned.mp4` are matched to `<base>.plan.json`, so
post-processed copies still show their segments.

## Server routes

| Route | |
| --- | --- |
| `/` | project hub |
| `/api/projects` | project list + progress |
| `/p/<id>/` | editor |
| `/p/<id>/notes/` | render notes page |
| `/p/<id>/project.json`, `/clips.json`, `/review.json`, `/render-notes.json` | data (GET) |
| `POST /p/<id>/save`, `POST /p/<id>/save-notes` | write review.json / render-notes.json (with backup) |
| `/p/<id>/media/{proxy,thumbs,strips,waves}/<file>` | prepared media |
| `/p/<id>/api/renders`, `/p/<id>/render/<file>.mp4` | renders and their segment timelines |

The server listens on 127.0.0.1 only.
